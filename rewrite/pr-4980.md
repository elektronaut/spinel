Fixes #4979.

Three problems hid each other. Under an empty or C locale Ruby's `Encoding.default_external` is US-ASCII, so `extract.rb` read the UTF-8 ruby/spec sources as US-ASCII, and `String#strip` raised `invalid byte sequence in US-ASCII` at the first non-ASCII line. That aborted the whole `Dir.glob` loop, leaving every later spec file unextracted (`language` got 498 of 2399 examples). `run.sh` then correctly exited 2 because listed examples were missing from the extraction, but the `rubyspec-gate` recipe ignored the status of both `extract.rb` and `run.sh`. With no results file written, `awk ... | wc -l` counted 0 regressions, and the gate printed `all N expected-PASS examples still pass`.

`extract.rb` now sets `Encoding.default_external = Encoding::UTF_8` before reading anything, so the extraction no longer depends on the caller's locale. The `rubyspec-gate` recipe removes the stale results TSV first so an old one can't stand in, and fails a suite if extraction fails, if `run.sh` fails, or if the results TSV has fewer rows than the expected-PASS list, printing `extraction failed`, `run.sh failed` or `ran X of Y expected-PASS examples` for it. The `rubyspec` measurement target now stops on an extractor failure (`|| exit 1`) instead of measuring a partial extraction. Nothing changes under a UTF-8 locale: the extracted output is byte-identical under `LANG=` and `LANG=C.UTF-8` for all six enrolled suites (same file count, same md5 of the concatenated output), and a full, clean run still takes the same `all N expected-PASS examples still pass` path.

Tests: there is no test file, since this is tooling with no Ruby reproducer. With the old extractor and `LANG=`, `make rubyspec-gate RUBYSPEC_SUITES="core/range language"` now prints `rubyspec-gate[language]: extraction failed` and exits non-zero. With this change, `make gate` run under an empty `LANG` extracts all 2399 `language` examples and all six rubyspec suites pass; the only failures are the two known environment failures (`pkg.tmpdir.tmpdir_expand_usable`, `socket_ipv6_and_class_methods`).

Not covered: the non-gate `make rubyspec` measurement also runs each example under CRuby (`ruby "$f"` in `run.sh`), and under an empty locale CRuby's own `default_external` differs, which could classify some encoding specs differently from a UTF-8 run. That only affects the measurement, not the gate, which sets `RUBYSPEC_GATE=1` and skips the CRuby run. Once this merges, the README's `export LANG=C.UTF-8` step is no longer needed for the gate, though keeping it does no harm.
