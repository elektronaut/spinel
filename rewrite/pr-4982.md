Fixes #4981.

`inherit_members` in `src/analyze_scope.c` copied each of a parent's reader and writer flags into every subclass with `comp_add_reader`/`comp_add_writer`, without checking whether the subclass defines the method itself. So in `Grand (attr_accessor :x) < Parent (def x=) < Mid (attr_writer :x) < Leaf`, `Parent` held `Grand`'s writer flag under its own `def x=`, and `Mid` got it twice: once inherited and once from its own `attr_writer`. `super_lands_on_attr` (added for #4909) decides whether a `super` lands on an attribute by checking whether the parent holds the same flag. If it does, it treats the class as having only inherited the attribute. It therefore walked past `Mid`'s real `attr_writer` and dispatched `Leaf`'s `super` to `Parent`'s def, so `l.x = 3` stored `30`. The stale flag also broke calls without `super`: any class below the def, including a plain `class Child < Parent; end`, read and wrote the ivar directly instead of calling the def, which gave a silently wrong value (`3` instead of `31`).

A reader or writer flag is no longer copied into a class that defines the same method itself. `comp_method_in_class` is checked for `name` or `name=` before the flag is added, so the def ends the attribute's inheritance for that class and everything below it. A class further down that re-declares the attribute gets the flag only from its own declaration, so `super_lands_on_attr` sees it as `Mid`'s own writer and stops there. Nothing changes for classes that don't override the attribute: they inherit the flags as before, and the existing `super_into_attr` test from #4909 still passes.

Tests: `test/super_attr_mid_redeclare.rb` is the issue's reproducer (the writer reached through `super`). It also covers the same shape with `attr_reader` and a reader `super`, a class under the def that re-declares only the writer and still reads through the def, and a plain subclass under the def with no `super`. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two failures that are already known in this container (`pkg.tmpdir.tmpdir_expand_usable` because it runs as root, and `socket_ipv6_and_class_methods` because there is no UDP).

Not covered: the check only looks at a `def` in the class itself. A `def` that the middle class gets from an included module doesn't stop the flag, and that shape wasn't tested.
