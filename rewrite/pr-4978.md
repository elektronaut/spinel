Fixes #4977.

The yield-inlining pass in `src/analyze.c` always marks a method with an anonymous `&` parameter as yielding, because the block has no name it could escape through. A named `&blk` forwarder whose callee keeps the block gets an escape edge (#3772) and stays a real function, so `a_block_is_lifted` gives the literal block's captures cells. The anonymous forwarder is spliced into the caller instead, and the literal block lands on the forwarded call (`@keeper.install(&)`), where codegen materializes it as a proc that outlives the call. `mark_proc_captures` only knew one shape of an inlined forwarder whose block still becomes a proc: one that forwards to a poly receiver (`a_block_forwarded_into_poly`). So the block's captured locals got no cells. A block that read one was refused by `emit_proc_literal` ("uncaptured outer variable"), and a block that wrote a value-type local wrote to a by-value copy, so the caller never saw the change.

The new `a_scope_forwards_block_to_keeper` asks, for a yield-inlined scope, whether a `&` or `&blk` forward (a named one only if it forwards this method's own block parameter) reaches a method that takes a real named `&block` and isn't inlined. It follows further inlined forwarders up to 4 links deep. `a_block_forwarded_into_poly` now also checks this and is renamed `a_block_forwarded_to_proc`. Like the poly case, it only feeds capture marking and the "cell outlives the call" flag, not the inlining decision, so the anonymous forwarder is still spliced and the code generated for it doesn't change. Blocks that aren't forwarded into a keeper are unaffected.

Tests: `test/anon_block_forward_capture.rb` covers four shapes. An endless `def install(&) = keeper.install(&)` with a block that sets a field on a captured local (the issue's first shape). The same forwarder with a block that adds to a captured integer (the issue's second shape). Two anonymous forwarders in a row before the keeper. An anonymous forward to a keeper on self (`install(&)` calling `keep(&blk)`), which on master compiled but printed `"got"` where CRuby prints `"got 1 2"`. The test fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`, which fail on master too for environmental reasons (running as root, no UDP).

Not covered: a named `&blk` forwarder that forwards into an anonymous `&` forwarder that forwards into a keeper still loses the block completely ("undefined method 'call' for nil"), even with no captures. The nested splice doesn't resolve the inner anonymous `&` back to the outer literal block (`resolve_forwarded_block` in `src/codegen_fold.c`), which is a separate bug. Also, a block forwarded this way that writes an ivar rather than a local still loses the write. That looks like the proc's `self` being wrong and has nothing to do with capture cells.

This was found in the badline C64 emulator, where `Computer#install_debug_register(&)` forwards to `address_bus.install_debug_register(&)`.
