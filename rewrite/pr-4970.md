Fixes #4969.

The direct-call arity check in `emit_args_filled` (`src/codegen_fold.c`) had three gaps. Keyword parameters live in `pnames[]` alongside the positional ones, and the check counted every entry as a positional slot, so `def m(x, k: 1)` looked like it took two positionals and `m(3, 4)` passed, with the 4 bound nowhere. Any callee with a `**kw` was skipped outright, so `def f(x, **kw)` called as `f(3, 4)` silently dropped the 4. And a braceless keyword hash none of whose keys named a parameter was always counted as one more positional (the options-hash idiom), even when the callee declares keywords; Ruby treats the hash as keywords in that case, so `g(1, j: 2)` against `def g(x, y = 7, k: 1)` should raise `unknown keyword: :j` rather than bind `{j: 2}` to `y`. The instance path in `emit_dispatch` had its own copy of the count with the same slot error, and it skipped every call carrying a keyword hash, which is why `Kw.new.m(3, 4)` and the self-call `m(3, 4)` inside an instance method bound silently as well.

The check is now one helper, `emit_call_arity_check`, called from both `emit_args_filled` and `emit_dispatch`; the dispatch's copy is gone. It skips declared keyword parameters and the `**kw` slot when counting positionals, judges a `**kw` callee's positional count in both directions (too many and too few), and, through the new `callee_declares_kwargs`, takes a keyword hash as keywords whenever the callee declares any keyword parameter. `emit_unknown_kwarg_raise` uses the same predicate and now returns early for a `**kw` callee, which accepts any key. A missing required keyword now reports `missing keyword: :k` even when the call has no keyword hash. What stays the same: a callee with no keyword parameters still takes a braceless hash positionally (`def opts(x, o = {})` called as `opts(1, j: 2)` gives `[1, {j: 2}]`), splat and double-splat calls and forwarding or synthesized parameters are still skipped, and a rest target still has only its shortfall judged (on the dispatch path it keeps measuring that itself), so no call shape that was checked before is checked differently except where the old count was wrong.

Tests: `test/surplus_arg_refusal.rb` holds the issue's three reproducers and their variants: a surplus positional into a keyword callee on the direct call, the instance call and the self-call inside an instance method; a surplus positional and a shortfall into a `**kw` callee, direct and on an instance; an unknown keyword into a callee with an optional positional and keywords, direct and on an instance; a missing required keyword; valid keyword and `**kw` calls that must keep working; a rest target's calls with and without a keyword hash; and the options-hash idiom for a callee without keywords. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known environment failures (`pkg.tmpdir.tmpdir_expand_usable` as root, `socket_ipv6_and_class_methods` with no UDP), and the rubyspec leg rerun under `LANG=C.UTF-8` keeps every expected pass.

Not covered: the inlined yield path, `emit_inline_call_x` in `src/codegen_iter.c`, still has no arity check, so `def y(x, k: 1) = yield(x + k)` called as `y(1, 2) { }` drops the 2. Calling the new helper there fixes it, but it trips `test/builtins_take_drop_while.rb`, which only passes today because a redefined top-level function resolves to its first definition (`comp_method_index_direct`); that is a separate bug and the yield-path check waits for it.
