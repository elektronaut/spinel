Fixes #4975.

When `Bus#install(&) = @register.handle(&)` is inlined into `Recorder#initialize`, the forwarded `&` resolves to the caller's literal block, and `emit_proc_literal` in `src/codegen.c` turns that block into a proc. It captured the current `g_self` as the proc's self. Inside the splice, `g_self` is the inlined callee's receiver (`_capv_1->__self = (void *)_t5`, the `Bus`). The proc body still casts `__self` to `sp_Recorder *`, so `@code = value` stored a boxed value in the `Bus`'s memory at `Recorder`'s `iv_code` offset. The `Recorder` kept `0`. The reproducer prints `0` only by luck: with more ivars or more calls, as in the variants test, the program segfaults on master.

`emit_proc_literal` is now a thin wrapper. When the block it turns into a proc is the spliced one (`create == g_block_id`, with the yield fallbacks set), it emits the proc under the self the inliner parked for that block (`g_yield_self_fallback` and its deref), the block's emitting class, and the block's own rename depth (`g_block_nren`). That is the same context `emit_block_invoke` already restores when it splices the block for a `yield`, so a forwarded block now gets the same self whether it is yielded to or turned into a proc. One change covers every site that turns the spliced block into a proc: anonymous `&`, named `&blk`, `Proc.new(&blk)`, forwarding through two inlined methods, and implicit-self calls inside the block. Any other proc literal, and any proc created outside an inline splice, goes through the old path unchanged.

Tests: `test/forwarded_block_ivar_write.rb` is the issue's reproducer. `test/forwarded_block_ivar_write_variants.rb` covers anonymous `&` with an ivar write and read, named `&blk` with an implicit-self call, `Proc.new(&blk)` inside the inlined method, forwarding through two inlined methods, and a stored proc that keeps updating its own object's ivar across several calls. Both fail on master (the first prints `0`, the second segfaults) and match CRuby 4.0 with this change. `make gate` is clean apart from the two known environment test failures (`pkg.tmpdir.tmpdir_expand_usable`, `socket_ipv6_and_class_methods`).

Not covered: `Klass.new(&)` into a stored-block `initialize`, and `super(&)` or zsuper into a parent that stores the block, from inside an inlined body, still drop the forwarded block or fail to compile. Those call sites never resolve the forwarded block, which is a separate cause. A forwarded block that captures an outer local is still refused with "proc referencing an uncaptured outer variable", same as before.
