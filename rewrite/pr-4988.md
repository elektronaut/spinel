Fixes #4987.

`struct_new_types_members` in `src/analyze_pass.c` types each Struct/Data member from the argument in its position at every `X.new` site. It read `S.new(*args)` as one positional argument: member 0 took the splat node's type and the members after it were treated as not supplied (nil). Meanwhile `S.new(1, 2)` elsewhere typed both members Integer, so the members stayed plain Integer slots. At run time the splat path spreads the array across the members and unboxes each element into its slot, so a String element was unboxed as an int (a garbage number) and the nil fill for a short array was unboxed as `0`. While fixing this, a sibling turned up that failed to compile on master: positional arguments beside a splat, as in `T.new(0, *rest)` or `T.new(*mid, "end")`, generated invalid C (`incompatible types when assigning to type 'sp_RbVal' from type 'sp_PolyArray *'`), because only a sole splat argument reached `emit_struct_splat_new` in `src/codegen_call.c`.

Now a member at or past the first splat is unified with POLY in `struct_new_types_members`, so it is boxed and can hold whatever element lands there or nil. A first attempt typed those members as the splat element type unioned with nil, but `issue_2971` showed that was wrong: `S.new(*[1])` gave `[1, 0]`, because Integer ∪ nil stays a plain Integer slot and the nil fill still unboxes as `0`. Boxing the member avoids that. In `src/codegen_call.c`, `emit_struct_splat_new` is split: the new `emit_struct_spread_new` spreads any array expression across the members, keeping the existing Data exact-count check and the Struct "struct size differs" check, and `emit_struct_splat_new` now just passes it the splat operand. The new `emit_struct_mixed_splat_new` handles positionals beside a splat by gathering every argument, in order, into one PolyArray and spreading that the same way; it declines (and the old path runs) when a splat operand has no array form. Members before the splat, construction sites without a splat, keyword arguments and keyword_init Structs are typed and emitted as before. ArgumentError for an overlong Struct or a short Data still matches CRuby.

Tests: `test/struct_new_splat_members.rb` covers the issue's reproducer (a splat of one Integer and of an Integer plus a String), a short Integer-array splat whose unset member must be nil, a leading positional plus a splat, a splat plus a trailing positional, and a two-member Data built through a splat. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known environment test failures (`pkg.tmpdir.tmpdir_expand_usable`, `socket_ipv6_and_class_methods`).
