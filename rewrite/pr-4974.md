Fixes #4973.

A method whose `&blk` or `&` is only forwarded is yield-inlined at its call sites, so its block param stops existing as a C local. `emit_method_call` handles this by running the call's block through `resolve_forwarded_block` and `emit_forwarded_proc_arg`, but the stored-block `initialize` arm of `emit_class_new_call` in `src/codegen_call.c` used the `BlockArgumentNode` as-is: a named `&blk` was emitted as `lv_blk`, which no inline site declares (a C build error), and an anonymous `&` has no expression, so it fell through to `NULL` (the stored handler is `nil` at run time). Fixing codegen alone isn't enough, because `src/analyze.c` resolved `Klass.new` as a class method `new` in two places: the forward-callee lookup in the inline-candidate pass, and `a_block_is_lifted`. Without a `def self.new` that lookup finds nothing, so forwarding into a storing `initialize`, or passing it a literal block, never counted as an escape. The forwarder stayed inlined and the block's captures got no cells, which is why a block reading a caller local (`box` in the second reproducer) or the outer block param (`handler` in the third) was refused as an uncaptured outer variable.

The `initialize` arm now resolves the block with `resolve_forwarded_block`, like `emit_method_call`, and writes a surviving anonymous `&` (one in a real-function body) with `emit_forwarded_proc_arg`. In both analyzer lookups, `Klass.new` falls back to `initialize` when the class has no `def self.new`, the same mapping `analyze.c` already uses elsewhere. A class that defines `self.new` still resolves to it, a literal block or a forwarded `&proc` expression still goes through the existing paths, and `initialize` methods that yield instead of storing the block are untouched.

Tests: `test/new_block_forwarding.rb` covers an anonymous `&` forwarded into `new` at top level and from an instance method, a named `&blk` with a positional argument and a block capturing a caller local, a literal block to `new` that reads the outer block param, and two install sites sharing a captured counter where the second block wins. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures (`pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`).

Not covered: an anonymous `&` forwarded into a storing callee with a block that captures a local (`def install(&) = Reg.new(&)` called as `install { |v| total += v }`) now reaches the handler but updates a copy of `total`, so it prints `0` where CRuby prints `7`. An anonymous `&` method is always treated as safe to inline, and a real function has no name for its block, so this needs anonymous `&` desugared to a synthetic named param, which touches every special case for anonymous `&`. A literal block reading the outer block param passed to a method on an ivar receiver (`@reg.set { |v| handler.call(v) }`) still fails to compile with `'_cell_handler' undeclared`, because the ivar's type isn't known yet when the inline-candidate pass runs.

Found in the badline C64 emulator, where `AddressBus#install_debug_register` calls `DebugRegister.new(@sid, &)`.
