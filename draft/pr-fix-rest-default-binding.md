title: A leading optional binds around a *rest

Fixes #N.

`arg_slot_for_param` maps each parameter to the argument that funds it when an optional sits ahead of a required parameter, which Ruby funds last. It gave up whenever the method had a `*rest` and returned the parameter's own index. So for `def r(a = {}, *rest, c)`, `r(5)` gave `a` argument 0 even though the trailing `c` needed it, and both ended up holding 5. `def r2(a = 1, b = 2, *rest, c, d)` called with two arguments bound them to `a` and `b` as well as to `c` and `d`. A second, independent gap was in the post-rest branch of `emit_args_filled`: it took every parameter with an index after the rest as a post and read it from the end of the positional arguments. A keyword declared after the posts (`def kq(*r, c, k: 0)`) matched that test too and was read from a position past the end of the arguments, so `kq(1, k: 2)` bound `k` its default and never looked up its key.

`arg_slot_for_param` now handles a rest by skipping it: the rest is funded last, with whatever is left once the leading requireds, the optionals and the posts are covered, so the trailing requireds are counted from after it. The rest slot itself maps to no argument. Cutting a `**kwrest` and the declared keywords from the positional list is already on master (00bac566), and this change builds on it. The post-rest branch in `emit_args_filled` now only takes indexes up to `rest_idx + npost_rest`, the bound the instance-dispatch path already had, so a later keyword falls through to the by-name binding below. Methods without a leading optional are untouched, since `arg_slot_for_param` still returns the plain positional index for them first.

Tests: `test/rest_leading_optional_slot.rb` is the issue's reproducer, plus `r` with a filled rest, `r2` with two optionals and two posts at every count from 2 to 5, `kk` (`def kk(a = {}, c, **kw)`, already right on master and kept as a guard) with and without keywords, `kr` (`def kr(a = :d, *r, c, k: 0)`) mixing a rest, a post and a keyword, the same `r` and `kk` as instance methods, and `kq` for a keyword after the posts. It fails on master and matches CRuby 4.0 with this change. After the rebase onto current master (a conflict with 00bac566 in `arg_slot_for_param`, resolved by keeping master's keyword trimming) the test passes; the gate below ran before the rebase. `make gate` was clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`, and two load-related flakes on this run: `bm_ackermann` hit the 10 s compile timeout under the gate's parallel load (a lone `make bench` is 62/62), and `ffi_io_buffer_arg_guards`, a thread-timing test whose generated C is identical to master's apart from `#line` paths, passed six times in a row standalone.

Not covered: a poly receiver whose method has this shape still raises NoMethodError for `q.r(5)`, because `poly_arm_count` in `src/codegen_call.c` keeps its old count rule for a leading optional beside a `*rest` (its comment points at the positional fallback removed here). That arm filter can be relaxed separately.
