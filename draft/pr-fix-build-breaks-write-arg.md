title: A write to a mutable-string local passed as an argument passes the handle

Fixes #N.

`buf` is a shared mutable-string local (`TY_STRBUF`, an `sp_String *` handle) because a block appends to it. The analyzer types `show`'s parameter from the argument node. For a write node that's the local's own type, `TY_STRBUF` (a plain read, `show(buf)`, gives String), so `s` became an `sp_String *` parameter. Codegen emits the write through its value form, which is the `const char *` copy. The argument-sequencing hoist in `emit_args_filled` (`src/codegen_fold.c`) declared `const char * _t1 = ({ lv_buf = ...; lv_buf; })` and then `sp_String * _t2 = _t1` for the parameter slot, and the C didn't compile. Nothing in the argument path treated a write to a `TY_STRBUF` local as a source of the handle.

A new helper, `emit_strbuf_local_write_handle`, handles a write to a `TY_STRBUF` local whose value has to be the handle: it runs the write as a statement (`emit_assign`) and yields the local's `sp_String *`. If the write was already hoisted into a temp, it yields that temp. `emit_args_filled` uses it when hoisting an argument for a `TY_STRBUF` parameter and declares the temp as `sp_String *`. `emit_arg_or_default_fill` uses it for a `TY_STRBUF` parameter before its existing shared-handle cases. So the parameter and the local are one object, as in Ruby: a mutation inside the callee shows through the caller's local. Any other argument, including a write to a non-`TY_STRBUF` local, gets 0 back from the helper and takes the existing path unchanged. The branch doesn't touch the write's expression form (`emit_expr_node` in `codegen_expr.c`), which has a separate bug for these locals (#N, `fix-array-new-block-string-local`). It doesn't depend on that fix, and the two touch different files.

Tests: `test/strbuf_write_as_arg.rb` covers the issue's reproducer; a callee that mutates its parameter (`bang(t = +"hi")`), where the caller's local sees the mutation; two side-effecting write arguments evaluated left to right (`pair(x = +"l", y = +"r")`); and the same shape as an argument to a method on an object (`Box.new.put(u = +"box")`). The file fails to compile on master (13 C errors) and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a method that returns its mutable-string parameter hands back a copy, so aliasing through the return value is lost. With `class Box; def put(s) = (s << "#"; s); end`, `u = +"box"; v = Box.new.put(u); u << "~"; p [v, u]` prints `["box#", "box#~"]`, where CRuby prints `["box#~", "box#~"]`. That happens on master too, with a plain `put(u)`, and is about how the return value is passed back, not about arguments.
