title: super in self.new is Class#new

Fixes #N.

Inside `def self.new`, `super` was treated like any class-method `super`: `emit_super` looked up `new` in the parent's class-method chain and, finding none, emitted the "super: no superclass method" NoMethodError. The analyzer did the same, so the `super` (and a static `C.new(7)` reaching that `self.new`) had no type, and a site that needed one, such as `puts C.new(7)`, was refused at compile time. Nothing bound the `super` arguments to `initialize`'s parameters or counted the class as instantiated either. In Ruby, when no ancestor defines a class method `new`, that `super` is `Class#new`: allocate the receiving class, which may be a subclass inheriting the `self.new`, and run its `initialize`. Separately, the two static `K.new` sites in `codegen_call.c` that call a user `self.new` never passed the receiving class, although `cmethod_takes_self_cls` makes such a method take one when its body reads `self` or `name` (#4217); an inherited `self.new` reading `name`, called on the subclass, failed in C with too few arguments.

A new `comp_super_is_class_new` (`compiler.c`) recognizes a `super` or bare `super` in a `self.new` with no class method `new` above it. The analyzer uses it to type the result as an instance of the class (boxed when a descendant can inherit the method), to bind its arguments to the `initialize` of each class that can receive it, and to mark those classes instantiated. `cmethod_takes_self_cls` makes such a method take the receiving class, and the new `emit_super_class_new` builds it: a direct constructor call when the class has no descendants, else a `switch` on the receiving class with one boxed arm per class. A bare `super` forwards the method's parameters in order. Both static `K.new` sites now pass the receiving class through `emit_cmethod_self_cls_arg`. A `super` whose ancestors do define a class method `new` resolves exactly as before. `super` in `self.new` of a Struct, Data, exception or native class, and a bare `super` from a `self.new` with keyword, rest or block parameters, are refused as unsupported rather than guessed at.

Tests: `test/super_in_selfnew_is_class_new.rb` covers the issue's reproducer, `super` with arguments both assigned and passed straight to `puts`, a bare `super` filling a default, an inherited `self.new` building the subclass with its own `initialize`, `super()` from a `self.new(*)`, and a static call reaching an inherited `self.new` that reads `name`. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered by this change alone: the same `super` reached through a Class value (`pick(i).new(7)` with `C` above) also needs the Class-value `self.new` dispatch from #N (`fix-class-value-new-arms-selfnew`), without which the call never reaches `C.self.new`. With both applied that shape matches CRuby as well; the two merge cleanly, and neither depends on the other.
