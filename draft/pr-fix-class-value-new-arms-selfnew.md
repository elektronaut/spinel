title: A Class value's new reaches a class's own self.new

Fixes #N.

`k.new(...)` on a Class value goes through one of four `new` emitters in `codegen_call.c` (positional, zero-argument, keyword/splat in `emit_class_value_new_kw`, and the boxed receiver read out of a container), each a `switch` on `cls_id` with a constructor arm per class. None of them looked for a user `self.new`, so a class with one was built by its constructor instead. Before them, the generic class-method dispatch on a dynamic Class value (#2445) claimed any call whose name some class defines as a class method, `new` included. For `new` that dispatch had arms only for the classes with their own `self.new`, none for classes that construct normally, and it typed the result from those user methods alone: with a `self.new` returning a String, the call's boxed result was assigned a `const char *` and the C did not compile.

The class-method dispatch now leaves a poly-typed `new` to the `new` emitters. A new `emit_user_new_arm` gives a class with its own `self.new` (found through the class-method chain, so an inherited one counts) an arm that calls it, in all four emitters, and the result is boxed from the method's return type. On the hoisted paths the arm checks arity and raises ArgumentError, packs a `*rest` from the parameters around it, gives a `**kwrest` an empty hash, and binds declared keywords by name from the hoisted hash, because a sole keyword hash reaches the positional emitters as one boxed temp. It passes the receiving class when the body reads it (#4217), so an inherited `self.new` that reads `name` sees the subclass. Classes without a user `self.new` keep exactly the arms they had. A `self.new` that yields or takes a block, and a keyword hash reaching one with a `**kwrest` on the hoisted path, are refused as unsupported rather than miscompiled.

Tests: `test/class_value_new_user_selfnew.rb` is the issue's reproducer. `test/class_value_new_user_selfnew_arms.rb` covers a user `self.new` reached positionally, with zero arguments, through a splat, with keywords (one defaulted), with a rest between required parameters, with a `**kw`, through a boxed receiver read from a Hash, and an inherited `self.new` reading `name`, plus the ArgumentError for too many arguments; classes without one still construct alongside. Both fail on master and match CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a class that exists only as a Class value (never built by a static `A.new`) prints `#<A:0x…>` from `puts` instead of calling its own `to_s`, on master too. That is a separate bug, probably in how `puts` picks its `to_s` arms; the arms test builds `A` statically once to stay clear of it.
