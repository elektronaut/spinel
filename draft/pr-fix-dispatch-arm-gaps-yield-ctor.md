title: A Class value's new runs a yielding initialize through its proc form

Fixes #N.

An `initialize` that yields, or forwards an anonymous `&`, is inline-only like any yielding method: a constant `X.new` site splices its body after allocating through `sp_X_new` (`emit_ctor_yield_inline`), and `sp_X_new` itself only allocates. That works when the class is known at compile time, but every `new` whose class is known only at run time (`k.new` on a Class value, a Class read from a container, about ten arm emitters in all) builds its arms by calling `sp_X_new`, so the object came back with every ivar unset and no error. The splice's own fallback, when it declines, lands on the same allocation-only `sp_X_new`.

When the program contains a `new` whose receiver is not a constant, `pf_wanted` (`analyze.c`) now asks for a proc-form clone of a yielding `initialize`, the same kind of real function taking the block as an `sp_Proc *` that the poly dispatch uses for yielding methods (#3399). For a heap class whose `initialize` has such a clone (`ctor_init_proc_form`, `codegen.c`), `emit_class_new` splits the constructor: the old allocation body becomes `sp_X_new_noinit`, and `sp_X_new` allocates through it and then runs the clone with a NULL block, converting each parameter to the clone's type (and casting `self` when the `initialize` is inherited). The splicing site now allocates through `sp_X_new_noinit`, so a static `X.new { ... }` still runs the body exactly once, with its block. Changing `sp_X_new` fixes all the dynamic-`new` arm emitters at once without touching them. Programs with no dynamic `new` get no clone and the same constructors as before, and Struct and value-type classes are excluded because their constructors come from their own emitters.

Tests: `test/class_value_new_yielding_init.rb` is the issue's reproducer. `test/class_value_new_yielding_init_variants.rb` covers an `initialize` forwarding an anonymous `&`, an inherited yielding `initialize`, a zero-parameter one, a zero-argument `new` on a Class variable, and static sites with blocks, with a global counter checking each body runs exactly once. Both fail on master and match CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a value-type class with a yielding `initialize` still builds allocation-only through a Class value, because its constructor has its own emitter, which this change leaves alone.
