title: An op-assign on a poly array boxes a typed-array rhs

Fixes #N.

`emit_array_op_assign` (`src/codegen_stmt.c`) is shared by local, ivar, global and class-variable slots. For `-=`, `|=` and `&=` it returned 0 unless the right-hand side had the slot's own array kind (or was unknown), and for `+=` unless it had the slot's kind or was an empty `[]` literal. The binary `poly_array OP typed_array` arms in `src/codegen_call_recv.c` handle the mixed case by boxing the typed operand into a PolyArray first (`sp_IntArray_to_poly`, `sp_StrArray_to_poly_fmt`, `sp_FloatArray_to_poly`, and `sp_poly_set_operand` for a boxed right-hand side of a set op), but the op-assign had no such conversion. So on a `[1, "x"]` slot, `m -= ["x"]` on a local was refused, and on a global or ivar the emitter declined and the write fell through to the raw C `-` between an `sp_PolyArray *` and an `sp_StrArray *`, which didn't build.

A new `poly_array_rhs_conv` helper returns the conversion the binary path uses for a right-hand side of kind `vt`: the three typed-array boxers, plus `sp_poly_set_operand` for a boxed value in a set op only (the binary `+` has no run-time coercion either). `emit_array_op_assign` applies it in the set-op arm and the `+=` arm, and only when the slot is a PolyArray and the right-hand side has another kind; it wraps the emitted right-hand side in that call and continues with the same helpers as before. A same-kind right-hand side, an empty `[]` literal, a typed slot (Int, Float or Str array), and `*=` are all unchanged, so the new path is only taken where the op-assign used to be refused or produce invalid C, and it produces what `m = m OP rhs` already does.

Tests: `test/poly_array_op_assign_mixed.rb` is the issue's reproducer on a global, an ivar and a local, and also covers `+=`, `|=`, `&=` and `-=` with Integer, String and Float arrays on the right, and a boxed right-hand side holding an array (`m -= pairs[0]`, `m |= pairs[0]`) that goes through the run-time set coercion. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a slot that holds a single-type array with a right-hand side of another type is still refused, for example `m = [1, 2]; m -= ["x"]` or `m = ["a"]; m |= [1]`. The binary `m = m | [1]` works because inference widens the local to a poly array on that write, but the op-assign's inferred type (`NK_LocalVariableOperatorWriteNode` in `src/analyze_infer.c`) keeps the slot's kind, so fixing it needs an inference change across all slot kinds. It is a loud refusal, not a miscompile.
