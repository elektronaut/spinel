title: A default reading an earlier parameter binds beside a *rest and a **kwrest

Fixes #N.

A parameter default runs at the call site, where the callee's parameters don't exist. When a default reads an earlier parameter, each call path hoists the arguments into uniquely named call-site temps in order and registers a rename, so the default reads the temp in place of `lv_<param>` (#4431). All three paths limited that hoist to methods with no `*rest` and no `**kwrest`: `emit_args_filled` for direct calls, `emit_dispatch` for instance calls, and the poly receiver arm in `emit_poly_method_dispatch`. For `def m(n, *r, k: n + r.size)` and `def h(x, y = 7, z = x * 2, **kw)` the default was then emitted against `lv_n`, `lv_r` or `lv_x`, and the C build failed. The poly receiver arm also had gaps of its own that don't depend on a default: with no keyword hash, a declared keyword took a positional argument (`q.m(3, 1, 2)` on `def m(n, *r, k: 0)` bound `k` the 2); a post after the rest was picked by `a > r_idx` with no upper bound; and a parameter ahead of the rest could read an argument that belongs to the posts.

The hoist now covers a rest, its posts and a kwrest, binding each the way the plain path does. In `emit_args_filled`, a post reads from the tail of the positional arguments, a parameter ahead of the rest only from the arguments before the posts, the rest is packed with `emit_rest_pack_kwh` and the kwrest collected with `emit_kwrest_collect`, and a declared keyword binds only by name. In `emit_dispatch` the packed rest is aliased under a renamed local, so a later default can read it (`k: r.size`). Both the rest and the kwrest are packed with the parameter renames switched off: they are the caller's expressions, and without that a caller local sharing a parameter's name read the callee's temp, so `o.m(1, n, r)` packed `[1, 20]`, not `[10, 20]`. The poly arm now takes a post only up to `r_idx + npost`, keeps a parameter ahead of the rest off the posts' arguments, never feeds a declared keyword a positional, and binds a `**kwrest` to `{}` when the call passes no keywords. Calls with a splat into fixed parameters or a double-splat still skip the hoist, as before, and methods whose defaults don't read another parameter take none of these paths.

Tests: `test/default_reads_param_rest_kwrest.rb` is the issue's two reproducers plus more calls of each; `def g(a, b = a + 1, *rest, c)` (an optional default beside a rest and a post); `def s(a, *r, t: r.sum + a, **o)` (a rest and a kwrest together); the same methods called on an instance and through a poly receiver, including one with no keywords passed to a `**kw`; and caller locals named `n`, `r`, `x` and `kw` passed into methods whose parameters have those names. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a splat into the fixed parameters of such a method still keeps the default out of the hoist, so `def g(u, v = u * 2); g(*[1])` fails the C build with an undeclared `lv_u`, with or without a rest. That call shape needs the splat's run-time count first and is a separate change.
