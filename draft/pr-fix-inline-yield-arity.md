title: An inlined yielding method judges its call's count and binds a **kwrest

Fixes #N.

A call with a block to a method that yields is inlined at the call site by `emit_inline_call_x` (`src/codegen_iter.c`). It binds the callee's parameters by walking them in order and taking the argument in the same position (or the keyword of the same name), and before the loop it only asked `emit_unknown_kwarg_raise` about keys no parameter names (#4419). An argument no parameter reads was simply never looked at, and a parameter with no argument bound its zero value, so `y1 { }` on `def y1(x)` ran with `x` as 0 and `y(1, 2) { }` on `def y(x, k: 1)` dropped the 2, where the ordinary call path raises `ArgumentError`. The same loop had two more gaps. A `**kwrest` parameter was never collected, so it bound its nil default and `kw` read nil. And the positional test (`i < pos_argc`) didn't exclude keyword or `**kwrest` slots, so a surplus positional in `ykw(1, 2)` on `def ykw(a, **kw)` was bound into the kwrest's `sp_SymPolyHash *` slot, a C type error.

The inlined path now calls `emit_call_arity_check(c, m, argc, argv, 1)` before binding, the same count-and-keys judgement the other call paths use; that function and `emit_kwrest_collect` (both in `src/codegen_fold.c`) are no longer static and are declared in `codegen_internal.h`. A `...` forward keeps the keyword check alone, because it carries the forwarder's own parameters rather than a call's arguments. In the binding loop, the `**kwrest` slot takes the hash `emit_kwrest_collect` builds (boxed when the local is poly), as on the other call paths, and keyword and `**kwrest` parameters never take a positional. Everything else in the loop is unchanged: positional, optional, rest and block binding, the options-hash packing and the keyword lookups read the same arguments as before, and a call whose count and keys are right passes the check without a raise.

This builds on #4970 (`fix-surplus-arg-refusal`), which must merge first. The gate also needs #4972 (`fix-redefined-toplevel-def`): `test/builtins_take_drop_while.rb` redefines `tw` with another arity, and without that fix its calls reach the wrong definition, which this check now refuses.

Tests: `test/inline_yield_arity.rb` is the issue's reproducer, and covers too few and too many positionals, optional and rest parameters, a surplus positional against a keyword parameter, a missing required keyword and an unknown one, and `**kw` collection (explicit keywords, a `**h` splat whose key a declared keyword takes, no keywords at all, and a surplus positional). It fails on master and matches CRuby 4.0 with this change. On a merge of this branch with `fix-redefined-toplevel-def`, `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.
