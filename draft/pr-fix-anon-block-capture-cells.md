title: An anonymous & is a named block parameter to the analysis

Fixes #N.

Whether a method with a named `&blk` is inlined or kept as a real function depends on whether the block escapes: the analysis follows the `LocalVariableReadNode`s of the parameter's name, and if one is stored or passed to a method that keeps it, the method stays a real function taking an `sp_Proc *` and the block's captures of the caller's locals are celled. An anonymous `&` forward (a `BlockArgumentNode` with no expression) has no reads to follow, so `analyze.c` marked every method with an anonymous `&` as `yields`, always safe to inline. `def install(&) = R.set(&)` was spliced into its caller, the caller's literal block was turned into a proc inside the splice, and that proc declared its own `lv_total = 0` copied from the caller's value. The stored block's writes went to that copy. It couldn't simply be left un-inlined, because a real function has no C name for an anonymous block parameter.

A new desugar pass, `desugar_anon_block_param` in `src/analyze_desugar.c`, runs before any scope is built, right after `desugar_forwarding_to_rest_callee`. It names an anonymous block parameter `__anon_block`, the way `__anon_kwrest` names an anonymous `**`, and rewrites every anonymous `&` forward in that method's own body, including blocks and lambdas inside it, into `&__anon_block`. A nested `def`, `class`, `module` or singleton class is left alone, since its `&` belongs to its own method. From then on the named machinery decides: a forward into a method that keeps the block is no longer inlined, `install` becomes a real `sp_rb_install(sp_Proc *const lv___anon_block)`, the literal block is built as a proc at the call site, and `total` is celled. A forward into a yield-inlined callee still inlines, as before. `Method#parameters` maps the synthetic name back to `:&`, as CRuby reports it (on master, taking a `Method` of such a method didn't compile, since there was no function to point at). The existing special cases for an anonymous `&` stay in place: `fwd_drop_spent_anon_block_param` (#4625) already handles the named case, and the `blk_param[0] == 0` branches are now unreachable for a `def` but harmless. All 14 existing tests that use an anonymous `&` pass unchanged.

This relies on #5006 and #4974, both on master. With the parameter named, `super(&)` and `Klass.new(&)` in an inlined method go down the same path as their named forms, which read an undeclared local before those fixes.

Tests: `test/anon_block_capture_cells.rb` is the issue's reproducer. `test/anon_block_capture_cells_variants.rb` covers ivar reads and writes in a block stored through `&`, an implicit-self call in the block, two levels of anonymous forwarding (`Hub` to `Bus` to `Register`), two captured locals written by a stored block called twice, a captured array mutated through two levels, `#parameters` of an anonymous-`&` method, and `block_given?` through an anonymous forward (master refuses this file with "proc referencing an uncaptured outer variable"). Both fail on master and match CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`, and four benchmark ERRs (`bm_ackermann`, `bm_ao_render`, `bm_attr_accessor`, `bm_bigint_fib`) that hit the bench leg's 10 s compile timeout while the rest of the gate was starting. None of them uses a block parameter, and `make bench` run alone right after the gate gives 62 pass, 0 error.

Not covered: `#parameters` still omits an anonymous `*` or `**` entirely, where CRuby reports `[:rest, :*]` and `[:keyrest, :**]`. That's pre-existing and unrelated to the block parameter.
