title: A call reads a global, ivar or cvar receiver before its arguments run

Fixes #N.

The builtin call arms emit the receiver as an inline expression (`gv_a` for `$a`) and hoist each argument's setup code into `g_pre`, which is emitted as statements ahead of the one holding the call. For `$a + [replace]`, the array literal's prelude calls `replace`, which reassigns `$a`, and only afterwards does the call expression read `gv_a`. Ruby reads the receiver first. This isn't specific to one arm: Array `+`, `union`, `|` and `-`, String `+` and `==`, `include?` and Integer `+` all read the receiver late. In the issue's first reproducer the `include?` case happens to give the right answer, because it is `false` either way; with the ivar receiver it doesn't.

The fix is made once, in `emit_call_held` (`src/codegen_call.c`), ahead of all the arms. A new `recv_read_before_args` picks out calls whose receiver is a `GlobalVariableReadNode`, `InstanceVariableReadNode` or `ClassVariableReadNode` of a typed, non-object value, that have no block, whose method is one of a fixed list of operators and queries that don't change the receiver (`+ - * / % ** | & ^ == != < > <= >= <=>`, `union`, `difference`, `intersection`, `intersect?`, `include?`, `member?`, `eql?`), and where some argument `subtree_has_side_effect`. For those, the slot is read into a rooted temp in `g_pre` before any argument's prelude, and the receiver node is registered in the existing `g_argov_*` override table, so every arm reads the temp instead of the slot. Mutating methods are left out on purpose, because their arms may write the slot back through the same receiver node, which would then write the temp; `$x.push(gx)` was already right and still is. A call whose arguments have no side effect, or whose receiver is a local or a user object, is emitted exactly as before.

Tests: `test/recv_read_before_args.rb` is the issue's reproducers, and covers the global receiver with Array `+`, `union`, `include?` and `|`, an array literal holding the global beside the call, String `+`, an ivar receiver with `+` and with `include?` (where the answer flips between true and false), a class variable receiver with `-`, a String global with `==`, an Integer global with `+`, and `$x.push(gx)` as a mutator control. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`; the gate run also showed six benchmark errors while a parallel build was loading the machine, and a standalone `make bench` right after gave 62 pass, 0 fail, 0 error.

Not covered: a local receiver captured by a proc that an argument calls (`a = [1]; f = -> { a = [2]; 3 }; a + [f.call]`), and user-object receivers, which go through their own dispatch paths.
