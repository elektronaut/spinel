title: A poly receiver's zero-argument arm raises when its method needs arguments

Fixes #N.

The zero-argument path of `emit_poly_method_dispatch` in `src/codegen_call.c` kept a class's switch arm only when the method's `nrequired` was 0. That test was wrong in two ways. `nrequired` is an index, not a count, so a leading optional (`def h(a = {}, c)`) has `nrequired == 2` and its arm was dropped even though the method needs just one argument. And a method that really does need arguments was also dropped instead of refusing the call. In both cases `o.h` fell through to the switch's default and raised `NoMethodError`, where CRuby raises `ArgumentError`. The same `nrequired == 0` test decided whether class 0 and primitive reopens count as candidates for the dispatch key, and whether a method reopened on `Object` becomes the default arm, so `class Object; def zz(x)` called as `5.zz` through a poly slot answered `NoMethodError` as well. #4958 fixed this shortfall in the argument form of the dispatch.

A new helper, `poly_arm_refuses_none`, asks #4958's `poly_arm_count` whether a method refuses a zero-argument call and returns CRuby's "given 0, expected ..." text. If a class's method refuses, its arm becomes `case k: sp_raise_cls("ArgumentError", "wrong number of arguments (given 0, expected ...)")`, unless the class also has a reader of that name, in which case the existing reader arm stays. A refusing method counts toward the class-0 and primitive-reopen dispatch keys, as #4958 did for the argument form, so a boxed scalar whose `cls_id` is 0 isn't caught by class 0's new arm. A refusing method reopened on `Object` becomes the switch's `default:` `ArgumentError`. Arms that bind are unchanged: they still require `nrequired == 0`. The change only adds arms for calls that raised the wrong error before.

Tests: `test/poly_zero_arg_arity.rb` is the issue's reproducer. `test/poly_zero_arg_arity_variants.rb` covers a plain required parameter (`expected 1`), a post-rest required parameter `def t(*r, x)` (`expected 1+`), an optional-then-required parameter `def g(a, b = 2)` (`expected 1..2`), arms that bind next to arms that refuse in one dispatch, a class whose `h` is an `attr_reader`, and the `Object`-reopen default arm with `Integer` and `String` receivers. Both fail on master and match CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.

Not covered: a yielding method with parameters that is reached only through a zero-argument poly call still fails to compile, because its proc form's parameters end up untyped. That's in the analyzer, not dispatch, and is fixed separately in #N (`fix-build-breaks-zero-arg-pf`).
