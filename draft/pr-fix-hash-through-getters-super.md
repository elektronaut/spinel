title: A write through a super getter reaches the ancestor's ivar

Fixes #N.

An index write through a zero-argument call (`s.cache["x"] = "y"`) is evidence for the ivar the called method answers; `getter_ivar_targets` finds those (class, ivar) pairs by looking, for the receiver's class and each descendant, at the method the call dispatches to and taking the ivars its body exits with (or the ivar an `attr_reader` names). Three things went wrong. A body of bare `super` exits with no ivar, so `def cache = super` was no getter and the write credited nothing: `@c` stayed Integer-keyed and the String key could not be stored. A class carries its parent's readers as its own copy, so a subclass method over an inherited `attr_reader` looked like a tie between the method and the reader, and neither branch won. And each class keeps its own copy of an inherited ivar's type: crediting only the getter's defining class widened the subclass's copy while the base class, which writes the ivar in `put`, kept its narrower one, and the up-merge after the fixpoint unified the two into a plain box, so the store raised TypeError. That last part did not need `super` at all: a subclass `def cache = @c` over a hash the base class fills failed the same way.

`getter_ivar_targets` now follows a chain: when the dispatched method's last expression is a bare `super` or `super()` with no block (`is_bare_super`), it moves to the parent of the defining class and looks the name up again, up to eight hops, until it reaches a method that exits with an ivar or a reader. A method defined in the same class as a reader the parent also has is treated as the override. The write then credits the ivar's copy in every class from the defining class up to the root, or from the dispatching class up when the chain went through `super`, so the base class's copy widens with the rest. Getters with arguments, `super` with arguments or a block, and methods whose body is anything other than an ivar, a reader or a bare `super` are handled as before; the extra crediting only reaches ancestors that actually have the ivar, which already share the object's storage.

Tests: `test/hash_write_through_super_getter.rb` is the issue's first reproducer; a three-level chain where an `attr_reader` in the base class is overridden by `def tbl = super()` and then `def tbl = super`, written with a Symbol key and a Float value and read back with arithmetic; and the issue's second reproducer, a subclass `def cache = @c` over a hash its base class fills. It fails on master and matches CRuby 4.0 with this change. `make gate` is clean apart from the two known sandbox failures, `pkg.tmpdir.tmpdir_expand_usable` and `socket_ipv6_and_class_methods`.
